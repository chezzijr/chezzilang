# Gaps archive: wave 8 and the dogfood passes (2026-08-17/18) (moved verbatim from `docs/history/bug-hunts/gaps-archive.md` lines 468-1067)

## Session log — 2026-08-18 (`W8-43` — the structural-depth budget is now SHARED across nested protocol-hook re-entries)

**One row, filed already-CLOSED.** Found while working the wave-9 backlog, not by a gate. A user
`eq`/`str` hook dispatched from inside a native structural walk re-entered the VM and started a FRESH
depth-0 walk, so neither guard could fire — call depth stayed far below its 10 000 cap while the
*product* of hook-nesting depth × per-hook walk depth grew without bound, and the process died by
host stack overflow. Measured on `target/release/chezzi` at `c97d24ff`, `ulimit -v 12000000`:

| program | pre-fix | post-fix | CPython 3.14 |
|---|---|---|---|
| `Leaf.eq` comparing two fresh 100-link chains, nested **5 000** deep | `fatal runtime error: stack overflow, aborting`, **rc=134**, core dumped, `still alive` never printed | `still alive`, **rc=0**, recoverable `maximum structural depth (10000) exceeded` | catchable `RecursionError: Stack overflow (used 8148 kB) in comparison`, rc=0 |
| the same at nesting **200** | prints `true`, **rc=0** (every level restarts at 0, so nothing faults) | recoverable `Err`, **rc=0** | `RecursionError` |

The d=200 measurement is why the regression test is scaled there rather than at 5 000: a SIGABRT
would take the whole `chz_suite_passes` gate down with it, while d=200 gives a fast, non-crashing RED
that is still ~20 000 structural levels against a 10 000 budget.

**Why nobody caught it.** The behaviour was **documented as deliberate in two source comments**
(`values_equal_guarded`'s "starts a FRESH depth-0 walk … bounded there by the call-depth guard" and
`stringify_into`'s "a `str` method re-stringifies at the *same* depth"), so every review that read
them read a design, not a defect — while `MAX_STRUCTURAL_DEPTH`'s own doc promised the opposite
("turns that into a recoverable `RuntimeError`"). Both comments are corrected in the fix commit, and
the sizing rationale at the constant now states the assumption that was false: the
`MAX_CALL_DEPTH`/`VM_STACK_BYTES` co-tuning assumes **O(1) native frames per call-depth level**,
which holds for `run_until` and for the `hash`/`compare` hooks but NOT for a structural walk nested
under a hook. **Detector coverage:** the CPython differential does classify signal-kills as findings
(since `W7-33`), but `src/difftest/generate.rs` has no user-struct-with-protocol-method feature, so a
hook-nested walk is structurally outside its corpus — this was not a tuning miss, it was out of
scope.

**The fix, and the alternative that fails.** `Vm::walk_base` carries the depth the enclosing walks
already consumed; the **5 FAULTING** `MAX_STRUCTURAL_DEPTH` comparisons test `walk_base + depth`
(including the ones that cannot themselves re-enter — each can still run *inside* a hook), and the 4
`run_proto` dispatches with a live structural
`depth` in scope go through a panic-safe `Vm::guarded_walk`. The cheaper-looking alternative —
charge `depth` to `call_depth` around each hook — **fails**, because `GenCtx` carries its own
`call_depth` and the generator resume swaps it, so a generator driven from inside a hook would swap
the charge away. A plain `Vm` field is not swapped there, which is exactly right: the generator's
frames are on the same host stack.

**The correction the first cut needed: a DEGRADING guard must not share the budget.** All seven
guards were charged initially, and two of them do not fault — `cyclic_walk` stores the map/set key by
reference, `snapshot_value` aliases the tail. Charging those two silently pushed an ORDINARY shallow
acyclic key into the degrade branch whenever it was inserted from inside a hook running at depth, so
a later mutation of the caller's value reached the stored key: `4998 -> true`, `4999 -> false` on one
and the same program, `true` at every depth pre-branch. **The general rule, worth more than the two
lines it cost: charging a stack-safety guard is only sound when its over-budget branch FAULTS.** A
faulting guard that fires early is a conservative, visible refusal; a degrading one that fires early
is a wrong answer with nothing to observe it. Both are back on the bare `depth` and pinned by
`tests/chz/spec/eq_protocol_containers_test.chz::key_inserted_from_a_deep_eq_hook_is_still_snapshotted` at both depths.

### The dedupe that matters: wave 9's `D4`/`D5` are `W8-3`, not new rows

`W8-3` is filed as *\"`Shared.set()` inside `Shared.update()` loses the write\"* — a **same-task
reentrancy** row. Wave 9 hit the same defect from two other directions, and the three only make sense
together, so they are folded into that row rather than filed separately:

```
# (a) CROSS-TASK — the clobbering set is on ANOTHER task
s := Shared(0)
fn slow(x: int) -> int:
    time.sleep_ms(300)
    return x + 1
parallel:
    spawn: s.update(slow)              # reads 0, sleeps 300ms, writes 1
    spawn:
        time.sleep_ms(100)
        s.set(100)                     # lands mid-"RMW"
print("s = {s.get()}")                 # → s = 1        (threads 1/2/4, identical)
                                       #   Go mutex     → 100   (nothing lost)
```

```
# (b) CROSS-BOX update-in-update — hangs forever, and the docs bless this exact program
a := Shared(1); b := Shared(2)
fn bumpb(x: int) -> int: ...  b.update(...)  ...      # a's closure takes b
fn bumpa(y: int) -> int: ...  a.update(...)  ...      # b's closure takes a
parallel:
    spawn: a.update(bumpb)
    spawn: b.update(bumpa)
# → rc=124 at 1/2/4 threads, no output, no deadlock report
# docs/reference/concurrency.md:605: "(Re-entering a *different* box, or a same-box read/get, is fine.)"
```

```
# (c) ...and --timeout cannot reach it: the same body as a `test fn`
$ chezzi test --timeout=2000 inv_test.chz     → rc=124        (the RUNNER hangs)
$ chezzi test --timeout=2000 spin_test.chz    → "1 timed out" (control: the flag works)
```

**One root cause for all of it, and it is documented as deliberate:** `docs/reference/concurrency.md:598` says
`read`/`write` *\"copy the value out of the lock and **drop the guard before running the closure**\"* —
so `update` is not a critical section at all. Two lines above it, `:596` promises the opposite:
*\"the whole `write` is serialised so concurrent writers can't lose each other's updates.\"* The same
paragraph contradicts itself, and (a) is what that contradiction costs.

**This also re-derives `W8-3`'s filed prescription, per the CLAUDE.md convention that a closed or
open row's *Fix* column must be re-measured before it is implemented.** W8-3's fix (a) says the lost
`set` should **fault** (`set on a box already write-locked by this task`). That is right for the
same-task shape and **wrong for (a) above**, where the clobbering `set` is on a *different* task and
faulting a healthy program would be the **[[parked-is-not-stuck]]** mistake — it must **block**. And
fixing the guard makes (b) *more* reachable, not less: today the lock inversion in (b) cannot happen
through `get` precisely *because* the guard is dropped. **So the deadlock verdict in W8-3's fix (b)
has to land in the same commit as the guard**, or holding the guard converts a silent wrong answer
into a new class of hang.

### Cross-cutting themes (the reporters', re-derived here)

1. **The oracle is configured not to look.** `W8-23` sits behind a deliberate `MAX_BOUND` cap at 1e12
   in the CPython differential — the one gate that would catch it is capped just below where it
   starts. `W8-42` sits behind this file's own \"format specs: one byte differs\" line, which is true
   *of the specs the differential generates*. A differential is excellent inside its configured
   window; the window is where the bugs are not.
2. **A fix applied to some arms of an N-way set** — wave 6's meta-finding, and still the highest-yield
   lever. `W8-23` (int↔int made exact, mixed arm left behind), `W8-31` (allow-list covers
   `List`/`Map`/tuple, forgets `struct`/`enum`/`fn`), ~~`W8-37`~~ (the W8-14/W8-15 span sweep reached
   `run` and `check`, not `test` — **closed 2026-08-27**, TICKET-010). Three independent instances in
   one pass.
3. **`chezzi test` was a second-class citizen** (~~`W8-37`~~, and `W8-13` before it, both closed
   2026-08-27). `run` and `check` had coordinates, traces and JSON before the project's *own* primary
   loop did.
4. **Docs that over-claim cost more than docs that under-claim.** Every lane praised the docs, then
   was misled by one: *\"precedence follows Python\"* (`W8-28`), *\"re-entering a different box is
   fine\"* (`W8-3` (b)), *\"`Err` on an unreadable root\"* (`W8-39`), *\"`parse` → `stringify`
   round-trips\"* (`W8-35`), *\"refuses to overwrite\"* (`W8-24`). Trust earned by the good 95% is
   spent on the bad 5%.
5. **A stale binary is invisible.** The reporters' box had **no C linker**, so `cargo build` failed
   and left an eight-day-old `target/release/chezzi` in place — and the *next* `cargo` invocation
   reports `Finished` because nothing changed. This is the same family as the two traps already in
   CLAUDE.md (shared `CARGO_TARGET_DIR`, worktree stale-binary), with a third mouth: **a build that
   FAILS also leaves a runnable binary behind**. Verify the binary contains the change, not that the
   build command exited 0.

### THE META-FINDING — none of W8-1..W8-17 was reachable by the standing gates

4375 Rust tests, 586 Chezzi tests at two worker counts, the CPython differential, and `cargo test
conformance` were **all green** while every one of these was live. That is not a gap in any one gate;
it is a statement about what the gates are shaped to see:

- **A silent wrong answer has no assertion to fail.** W8-2/W8-3/W8-4/W8-6 all return a plausible value
  and exit 0. A suite catches a wrong answer only where someone wrote down the right one — and nobody
  writes an assertion for behaviour they believe is impossible (a lost `Shared.set`, a discarded
  `Result`). This is the same shape as **`widening-untested-by-its-own-suite`**, one level up: *a
  behaviour nobody suspected is structurally untested by the suite written by people who did not
  suspect it.*
- **No gate measures performance.** W8-7 and W8-8 are pure timing facts. `benches/run.chz` measures
  single-task throughput, which is precisely the shape that cannot see either of them (W8-7 needs ≥2
  fibers in a scope to fire). (Partly addressed when those two closed: `tests/chezzi_threads_cli.rs`
  now asserts a >5.5× serialization ratio at `CHEZZI_THREADS=1` and the new
  `tests/chezzi_threads_sys_time.rs` asserts `sys < 0.03 * user` at the default worker count. Both are
  narrow gates over the two specific shapes; the general statement stands.)
- **No gate reads a message.** W8-13..W8-17 are all message-quality. The suite asserts *that* a
  diagnostic fires and often its exact text — never whether the text tells the reader what to do.
- **No gate executes prose.** All twelve W8-18 rows. `cargo test conformance` executes `grammar.bnf`
  and the goldens execute `examples/*.chz`, but a sentence in `stdlib.md` is unexecutable by
  construction, and **eight of the twelve were STALE rather than never-written** — they described
  behaviour that had since changed, which is exactly what CLAUDE.md's *"docs are part of the change,
  not a follow-up"* rule exists to prevent.
- **A detector scoped narrower than its surface reports success by silence.** W8-11: the FFI goldens
  are `#[cfg(target_os = "linux")]`, so `cargo test` is green on a Mac **with the entire FFI surface
  unexercised**. Same family as **`lossy-decode-blinds-a-comparison-oracle`** and W6-9b — when the
  oracle can't see the case, absence of failure is not evidence of correctness.

**Carry into the freeze:** a green suite measures the assertions you thought to write. The two
detectors that *did* earn their keep here are the ones that compare against something outside this
repo — the CPython differential (which found the `NaN` byte and nothing else, because there was nothing
else) and running the actual Go/Python/Rust program, which is what produced W8-3, W8-4, W8-5, W8-7,
W8-8, W8-9 and W8-12. That is CLAUDE.md's ancestor rule paying out at scale, and it is the argument for
`docs/design/roadmap.md` §2b's unbuilt **Go-paired-programs differential**.

### ~~The airlock trap that turned a real test green while it asserted nothing~~ — **CLOSED 2026-08-17**

Documented behaviour (`syntax.md` §11b) — a write to a captured local inside `spawn:` does not escape
the task — but worth its own note because of the failure mode:

```chezzi
results: List[str] = []
parallel:
    spawn:
        results = pmap(ids, ...)
for r in results:            # ZERO iterations — every assertion inside is SKIPPED
    assert r == "ok"
```
```
inside task: results=['a', 'b'] n=7
after join:  results=[] n=0      (Go, same shape: after join: results=[a b] n=7)
loop iterations=0
```

The compiler **can see** a local written inside a task and read after the join. A warning there costs
nothing and prevents the failure mode that erodes trust fastest — a green test that tested nothing.
This is the same *correct > silent > wrong* ordering as **`parked-is-not-stuck`**, applied to a check
rather than a verdict. Filed under W8-19's fix list rather than as its own row because the airlock
semantics are deliberate and unchanged; only the missing warning was at issue.

**CLOSED 2026-08-17 — the checker warns at the READ, and the airlock semantics are untouched.** The
repro above, verbatim, on the release binary:

```
warning (line 5, col 10): 'results' is read here as its pre-`spawn:` value — a captured binding
crosses the task airlock as an independent copy, so the write inside the `spawn:` block (line 4) is
not visible after the join (carry the value out on a Channel, or use a Shared)
iterations over 0
rc=0
```

Non-fatal, like its W8-2 sibling; the `Shared` rewrite of the same program is **silent** and prints
`2`. Four hooks, no dataflow pass: the taint is recorded once at the top of `check_assign`'s lvalue
`match` (so `xs[i] = v`, `p.f = v`, `a.b[0].c = v` all resolve to the binding that actually crosses,
and a fifth lvalue arm added later is covered without an edit), once in `infer_method_call` for an
in-place mutator, reported at the read in `infer_ident`, and taken/restored per frame in
`check_fn_body`.

**The warn/silent split IS a measured table, not a design.** Every shape was run on the pre-rule
binary and the rule follows what the parent actually observed after the join: reassigning a captured
local, `xs.push`, `xs[0] = 9`, `p.x = 9`, `m["a"] = 9`, the **module-top-level** form of the repro,
the implicit-nursery (bare `spawn:`) form, a captured module global, a spawn inside a `for` read after
the loop, and the two parent-side read-modify-writes (`xs = xs + [2]`, `n += 1` — measured `1`, not
`2`) all lose the write and all warn. `Shared.update`, `Channel.send`, a `defer:` block in the
**parent**, a task-local nested `fn`, and a parent overwrite that supersedes the task's write all
survive and stay silent. The handle-type exemption is not a second list to maintain: `mutates_receiver`
is keyed on the receiver **type**, so `Shared`/`RwShared`/`Atomic`/`Channel`/`Executor`/`Socket`/
`Listener`/`Writer`/`Reader` fall through — and `str.reverse` (returns `str`) vs `List.reverse`
(returns `nil`) is exactly why the key is the type and not the name.

**Two things measurement inverted while building it**, both recorded because they are what a
re-derivation would get wrong: (1) the "locals only" line the note implied is drawn in the wrong
place — at **module top level** the binding is scope 0, so the filed repro *verbatim* would not have
warned; the rule uses `is_captured`, not `is_local_capture`. (2) The `defer:` claim was backwards: it
is the **parent** `defer:` that is exempt (its write IS visible — measured `1`), while a `defer:`
nested inside `spawn:` is on the far side of the airlock and correctly taints.

**Seven deliberate ceilings, all under-warns, all pinned by tests so closing one fails loudly**
(`ponytail:` markers in `src/checker/`, numbered list in `syntax.md` §11b, same seven in
`concurrency.md`): per **frame**, so the taint crosses no `fn` boundary in either direction (a
*closure* body is an expression in the parent's frame and so still warns — measured, and deleting that
was a true positive a first cut nearly threw away); lexical order, not dataflow; builtin containers
only, so a user struct method that mutates `self` is invisible; re-declaring the name clears the taint
(which is what stops a merely-shadowing loop variable being reported — and the taint **does** carry a
scope coordinate, so a *block-local* shadow's taint dies with its block instead of being charged to the
outer binding); a partial parent-side `m[k] = v` / `p.f = v` untaints silently (it *may* supersede the
task's write and the checker cannot tell which — `parked-is-not-stuck`: decline rather than warn on
noise); a body declared inside the task is not summarized back to its call site; and, the mirror of the
partial-write rule, **a partial read of a partial write declines** (a task-side `p.count = …` read back
as `p.name` names a part the checker cannot match up, so `p.count` read back as `p.count` is missed —
the three mixed pairs still report, because there it *can* tell).

**The last two ceilings exist because the first cut OVER-warned, and it took an adversarial pass to
find it.** Both shapes were false warnings on correct code: a block-local shadow's taint was charged to
the outer binding (`xs := [10,20]`, an inner `if` block re-declaring `xs := [1]` and spawning
`xs.push(99)`, warned at a post-block `print(xs.len())` that correctly prints **2**), and a
field-granular write poisoned every later read of the root — including in a program that had already
applied the fix the message recommends (task writes `p.count` **and sends it on a `Channel`**, parent
reads only `p.name` → warned, printing the correct `bob`/`1`). A warning that fires after the user did
exactly what it told them to do is worse than no warning. Both were caught only by two isolated
prosecutors and a defender, not by the suite; the code comment at the time asserted the opposite
invariant (*"Under-warning, never over-warning"*), which is precisely the shape a green suite cannot
contradict.

**Over-fire evidence, re-run on the release binary:** the `Shared` and `Channel` rewrites of the
repro, a 3-worker pool over a closed `Channel`, an `Executor` fan-out of 10 jobs into a `Shared` — all
silent. The whole `tests/chz` suite emits **zero** warning lines at both worker counts, including all
13 sites of `tests/chz/spec/airlock_shared_binding_test.chz`. Nothing was silenced to get there.

### Language milestones decided out of this pass (W8-21, W8-22) — NOT dogfood findings

Two design decisions came out of the W8-2 / W8-19 discussion on 2026-08-17. They are filed as rows so
the **rejected** alternatives and the ancestor survey survive, which is the part that rots first.

**W8-21 — success-coercion at `T?` / `T!E` sinks. CLOSED 2026-08-30 (TICKET-025).** The syntax already
shipped; the coercion is now implemented — a bare success value at a declared `T?`/`T!E` return sink
(a `fn`/closure return, incl. inline-expr body, and a bare `return` at `Result[nil, E]`) coerces to
`Some(v)`/`Ok(v)` via a checker-produced `RetCoerceTable` the type-blind compiler consumes verbatim at
its four return-sink lowerings. Decided: **exactly two coercions, both on the success side**
(`T`→`Some`, `T`→`Ok`). The proposal originally had a third, `E` → `T!E`, and killing it is the design
content:

| ancestor | coerces value → error-union? | how the overlap is avoided |
|---|---|---|
| Zig | yes | error side is an **error set** — a distinct kind, **no payload** (documented; not re-run, no toolchain here) |
| Swift / Kotlin / C# | optional only | errors live in `throws`/exceptions, absent from the return type |
| Rust | **no** | never offered — measured: `error[E0308]: expected \`Result<String, String>\`, found \`String\`` |
| Go | n/a | **position** decides, not type — measured: `("ok", nil)` / `("", boom)` |

**Nobody resolves the overlap; they all make it unrepresentable.** Zig buys the third rule by giving up
error payloads — Chezzi's `Error` has `.message()` and `E` is arbitrary, so that trade is already spent.
And the overlap here is not theoretical: `str` → `Error` is a **general** assignability rule (measured:
`e: Error = "boom"` compiles), so every `str` satisfies both sides of a `str!` sink — **34 sites**
(`Result[str]` ×19, `str!` ×15) against the 81 `return Err(` the rule would have saved. The replacement
is the **`!"..."`** sugar: the sigil supplies exactly the disambiguation types cannot.

**W8-22 — a caught `Error` carries its origin. CLOSED 2026-08-30 (TICKET-026).** The location already
existed and was discarded at one line (`src/vm/exec.rs:1392`, pre-fix); `e.line()`/`e.col()`/`e.file()`
now read it back. **The prescription this row originally recommended — a new native struct replacing
the `Err` payload — was measured wrong and was NOT built:** it breaks `e == "boom"` and the `Err('...')`
repr two suite tests assert. The payload stays `Obj::Str`; the origin rides in a `GcRef`-keyed side
table on `Heap`, stamped at the three `recover:` boundaries and pruned in `Heap::sweep`. The 336
`Err("...")` sites don't move, and neither does `==` or display for a user-constructed error. Ancestors
split evenly (Python yes, Zig debug-only, Rust and Go no), so this stayed a real choice; the shipped
shape is **construction span only, default rendering unchanged**, reusing `Program::file_path`,
`lexer::render_span` and `Program::modules` (the `Span.file` → path resolvers `W8-14`/`W8-15` landed).
