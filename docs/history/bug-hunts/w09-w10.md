## Session log — 2026-09-05 (bug-hunt wave 10: 26 confirmed findings, W10-1..W10-26, filed as TICKET-060..069)

**Shape of the pass.** Six agents over the same disjoint domains as wave 9 (airlock/capture/generators,
cancel/defer/recover + sync primitives, checker⊋compiler, core-vs-CPython, stdlib, FFI/modules/CLI/test
runner), ~400 probe programs; every candidate re-run by the main loop on the release binary at
`CHEZZI_THREADS=1` and default before filing. 30 candidates → 26 confirmed, 2 documented-by-design
(the airlock install rule, `concurrency.md:1428`; wave-9's own decision), 2 left as decisions (a fn body
reading a `:=` global declared below it; `1 < x < 3` chaining, landed under TICKET-077 — Python-style
chaining, all seven comparisons at one precedence level). The `--serial` oracle the hunt prompt
still names is gone (2026-08-16): the oracles were the two-worker-count diff plus a RUN Go/Python/Rust
reference, exactly as wave 9.

**Where the 26 came from.** Domains wave 9 called clean produced most of them, from COMBINATIONS wave 9
did not try: a channel op *inside* a native re-entry *in the main task* (W10-1), a fault *while the
owner* is parked (W10-16), a guard-waiter *plus* a channel park (W10-15), a pointer *into* an argument
(W10-6), an alias *in a pattern* (W10-4), a `None` binding *written after* a typed read (W10-5 — the
exact write shape W8-46's read-only measurement did not cover). One P0 is memory-unsafe from
check-clean code (W10-6). Five are the test runner silently reporting PASS or losing a diagnostic
(W10-9..W10-12) — none reachable by a gate that reads exit codes. Two are quadratic stdlib paths
(W10-22), the W8-34 class again, found by timing, not by assertion.

**Tickets.** Related rows were bundled by seam: 060 (cffi runtime: W10-6, W10-8), 061 (FFI surface:
W10-7, W10-14), 062 (scheduler verdicts: W10-16, W10-1), 063 (guard-park hang + test wall clock:
W10-15), 064 (checker soundness: W10-5), 065 (checker false-rejects: W10-2, W10-4), 066 (parser/desugar:
W10-3, W10-17, W10-20), 067 (test runner + `--errors=json`: W10-9..13), 068 (quadratic builders:
W10-22), 069 (stdlib contracts: W10-18, W10-21, W10-23..26). W10-19 was documented in place. The
regex dialect list gained its fifth RE2 difference (empty match abutting a previous match is dropped)
in the same commit.

## Session log — 2026-09-03/05 (bug-hunt wave 9: 8 findings, all 8 FIXED and post-merge verified; plus one test-infra gap, W9-9)

**Shape of the pass.** Six agents over disjoint domains (airlock/capture, cancel/defer/recover/generators,
channel/nursery/Shared/Executor, checker⊋compiler, core language, stdlib+CLI), ~450 probe programs, each
finding re-verified by the main loop on the release binary before filing. Every ticket was then judged at
its plan gate and every merged fix re-run on the merged binary rather than trusted from the gate — which
`docs/contributing/gaps.md`'s own history says is required (`auto-task review unreliable`).

**The mechanical oracles found nothing, and that is the headline.** Run beyond their CI ranges:
panic-fuzz seeds `2000..25000` → 0 findings in 23 000; the CPython differential seeds `5000..12000` →
0 in 7 000; `--floats` seeds `20000..26000` → 0 in 6 000; the 7 FFI goldens → 0. Large curated
surfaces were byte-identical to CPython: 1160 format specs (Chezzi statically rejects 325 and CPython
raises on exactly those 325), 400 unicode string-method cases, 400 base64/hex/url, 400 CSV, 510
datetime, 432 regex, 300 JSON round-trips. **All eight findings came from hand-built adversarial
programs judged against a RUN reference program**, not from generators — the same lesson W8 recorded:
a green suite measures the assertions you thought to write.

**What the eight were.** Three silent wrong answers (W9-1 airlock third copy, W9-3 `eq` bound
laundered through a protocol slot, W9-5 the newtype/DEC-029 inconsistency), one silent hang at the
default worker count (W9-2 Executor), three false rejections of programs the ancestors accept (W9-4
expected-type sinks, W9-6 turbofish forwarding, W9-8 BOM), and one wrong-position family (W9-7 JSON).
**None was reachable by the standing gates**: a silent wrong answer has no assertion to fail, a hang
has no exit code to check, and a message position no test reads.

**One filed ticket was WRONG, and the pipeline caught it, not the hunt.** W9-5 as filed claimed the
duplicate-declaration guard missed `struct S` + `fn S`. That pair is DEC-029, active and shipped in
`std/path.chz`; the filed fix would have deleted a working feature. The planning stage refused the
premise and asked. **The lesson is the one already in this file for closed rows: read the decision
records before filing, and read a closed row's PRESCRIPTION before implementing it.** What survived
was narrower and real — `newtype` was the lone host disagreeing with DEC-029.

**A subagent's measurement was also wrong, in the direction that would have blocked a good fix.** The
implementing stage for W9-2 reported a race its own change had introduced, with `0/30` on base against
`3/30` on branch. Re-measured by the main loop at 40 repeats each: **branch 3/40, main 2/40** — no
delta, and the test (`try_recv_drains_residue_after_blocking_recv_resumes`) was already the twelfth
name on TICKET-050's deferred list. A 30-sample run that misses a ~5% flake reads as proof of zero.
**Corollary for any future flake comparison: size the sample so a 5% rate cannot read as 0, and check
the failing test's NAME against the known-flaky list before reasoning about its shape.**

**The pass's largest cost was environmental, not technical.** Four tickets escalated on a RED suite
that had nothing to do with them, because the dispatcher had been started under a supervisor missing
`pipeline run -j 1`, so stages ran cargo concurrently on 12 cores. `.project/run-supervised.sh` is the
supervisor of record and already handles this (it also distinguishes the deliberate
"dispatcher source changed" exit from a human stop). Once stages were serialised, `bash
.project/run-test.sh` on the same base the gate had called RED exited **0**, every target green. The
three tests that reddened under load are W9-9.

**Doc drift fixed in place rather than ticketed** (commit `b0c76e52`): the retired generator
reach-gate claim in `docs/reference/syntax.md:1438` and `docs/design/roadmap.md:793` (the reach-gate + poison-snapshot
model was retired 2026-07-21; a module-global generator crosses BY VALUE); the `RwShared` example at
`docs/reference/concurrency.md:603` that did not compile (`insert` is a List method, `sum_values` never
existed); and the `cancelled()` complexity claim in `std/cancel.chz:34`, `docs/reference/stdlib.md` and
`docs/reference/concurrency.md`, which said **O(depth), ~0.29 µs per ancestor** while the measured cost is
QUADRATIC — 0.53 µs at depth 0, 178 µs at 100, **2360 µs at 400** — against Go's flat O(1) `ctx.Err()`.
`docs/contributing/benchmarks.md:1859` had recorded the superlinearity and its cause all along; only the
user-facing claims were stale. That is the standing pattern: **a constant measured at depth ≤ 5 does
not describe the curve.**
