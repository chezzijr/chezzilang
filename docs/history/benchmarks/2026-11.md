(`DRAIN_PROTO`, `Op::Drain(DrainStep)`, `src/vm/defer_drain.rs`) that calls each `defer` record
through a real call op, instead of a nested `run_until` under `guarded`. Release binaries,

`defer.chz` is 500k calls, each with a `defer:` closure and a `defer xs.pop()`. The first trampoline
cost +13.75% (5,861,201,571): four ops per record (`Load`, `Call`, `Pop`, `Done`) dispatched through
`step`, a `String` clone of a method defer's name per call, and a drain continuation that carried an
`Unwind` inline. Cuts, in order (instructions:u): the drain's start loads the first record and the
steps become `Call` and `Next` (`Next` pops, then loads the next record or ends the drain), so a
record costs two ops: 5,440,634,639 (+5.6%); `Op::Drain` dispatched in `run_until`'s inlined arms:
5,362,635,995 (+4.1%); `DrainCont::Unwind` boxed: 5,318,448,693 (+3.2%); `take_escape_park` tests
the park in place and `drain_escaped_nursery`'s check is inlined with its body out of line, both on
every return: 5,292,449,112 (+2.71%). A method defer's name is an `Arc<str>` (`Op::DeferMethod`,
`Deferred::Method`), so recording and calling it copies no string. Wall time: 711.4 ms ± 13.1 vs
base 711.2 ms ± 16.5 (hyperfine, 10 runs). The cap-0 send line measures the settle-wins
`halt_latch` snapshot each offered send takes; its `fault_trace` clone of `None` is a branch.

Scale (`tests/defer_park_scale.rs`, 2000 tasks that each wait in a `defer`, `--threads=2`): 5 OS
threads, 0.47 s, `demotes=0`. Before: 2005 threads, 38.3 s (each wait demoted its worker).

each call; a destructor thread-local per call).
